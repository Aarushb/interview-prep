# Math and Geometry

## Pattern Overview
This pattern covers matrix traversal/transformation tricks (layer-by-layer rotation, spiral walks, using the matrix's own edges as O(1) markers) alongside numeric manipulation problems (digit arithmetic, cycle detection on generated sequences via Floyd's slow/fast pointers). There's no single unifying algorithm — recognizing which specific trick a problem calls for is the skill.

## When to Use It
- The problem operates on a 2D grid/matrix and asks you to traverse, rotate, or transform it in place.
- Keywords like "in-place", "rotate", "spiral order", "set to zero", "transpose".
- The problem is a numeric manipulation task disguised as an algorithm problem: digit-by-digit arithmetic, cycle detection on numbers, modular arithmetic, or simulating a physical/geometric process.
- Memory constraints push you toward O(1) extra space solutions using the matrix itself as scratch space (marking rows/columns, swapping in place).
- You need to detect a repeating cycle in a sequence generated by applying a function repeatedly to a number (classic sign: "will it terminate or loop forever?").

## Core Idea
Matrix problems in this pattern usually hinge on one of two traversal strategies. The first is **layer-by-layer processing**: think of the matrix as concentric square "rings" (like an onion), and either rotate/transform one ring at a time (Rotate Image) or walk the boundary of the current ring before shrinking the boundary inward (Spiral Matrix). Rotate Image specifically can be done with two classic decompositions: transpose the matrix then reverse each row (90° clockwise), which avoids tricky index math for four-way swaps. Spiral Matrix tracks four boundaries — `top`, `bottom`, `left`, `right` — and walks right along `top`, down along `right`, left along `bottom`, up along `left`, shrinking each boundary after its pass, until the boundaries cross.

The second matrix strategy is **using the matrix's own edges as O(1) markers**, as in Set Matrix Zeroes: rather than allocating a separate boolean grid to remember which rows/columns must become zero, use the first row and first column of the matrix itself as the marker array, with one extra boolean to handle the ambiguity of whether the first row/column itself needed zeroing.

The numeric half of this pattern (Happy Number, Plus One) is about treating numbers as sequences of digits or as nodes in an implicit function graph. Plus One is straightforward digit-array arithmetic: add 1 from the least significant digit, propagate carry, and handle the edge case of an all-9s number needing an extra leading digit. Happy Number reframes "does repeatedly summing squared digits eventually reach 1, or loop forever?" as a **cycle detection** problem on the sequence of values produced — exactly the same shape as Floyd's cycle detection (slow/fast pointers) used for linked lists, just applied to a numeric sequence generated by a transformation function instead of `node->next`.

## Complexity
- Time: O(n·m) for a full matrix pass (Rotate Image, Spiral Matrix, Set Matrix Zeroes) where n, m are matrix dimensions; O(d) for digit-array problems where d is the number of digits; O(log n) amortized per Floyd cycle step for Happy Number since digit-sum shrinks numbers rapidly.
- Space: O(1) extra space is achievable for all four matrix/digit problems in this set (in-place rotation, in-place zeroing using matrix markers, in-place digit carry); Happy Number's Floyd's-cycle version is O(1) space (vs. O(k) for a hash-set approach).

## C++ Template
```cpp
#include <bits/stdc++.h>
using namespace std;

// Layer-by-layer matrix boundary walk — covers Spiral Matrix and similar
// "process ring by ring" problems.
vector<int> spiralWalk(vector<vector<int>>& matrix) {
    vector<int> result;
    if (matrix.empty()) return result;
    int top = 0, bottom = (int)matrix.size() - 1;
    int left = 0, right = (int)matrix[0].size() - 1;

    while (top <= bottom && left <= right) {
        for (int c = left; c <= right; ++c) result.push_back(matrix[top][c]);
        ++top;
        for (int r = top; r <= bottom; ++r) result.push_back(matrix[r][right]);
        --right;
        if (top <= bottom) {
            for (int c = right; c >= left; --c) result.push_back(matrix[bottom][c]);
            --bottom;
        }
        if (left <= right) {
            for (int r = bottom; r >= top; --r) result.push_back(matrix[r][left]);
            ++left;
        }
    }
    return result;
}

// Floyd's cycle detection applied to a numeric sequence — covers Happy Number
// and any "does repeatedly applying f(x) reach a target or loop forever?" problem.
long long transform(long long x) {
    long long sum = 0;
    while (x > 0) {
        long long d = x % 10;
        sum += d * d;
        x /= 10;
    }
    return sum;
}

bool reachesOneEventually(long long n) {
    long long slow = n, fast = transform(n);
    while (fast != 1 && slow != fast) {
        slow = transform(slow);
        fast = transform(transform(fast));
    }
    return fast == 1;
}
```

## Common Pitfalls
- Rotating or transposing a matrix that isn't square when the algorithm assumes square dimensions (Rotate Image is always N×N on LeetCode, but double-check).
- Off-by-one errors in the shrinking boundaries for spiral traversal, especially the guards (`top <= bottom`, `left <= right`) needed before the second down/left pass to avoid re-visiting or skipping a row/column on non-square matrices.
- In Set Matrix Zeroes, overwriting the first row/column marker cells before you've finished reading them — must decide the zeroing order carefully (process the body first, then the first row/column, using a separate flag for whether column 0 itself needs zeroing).
- For Happy Number, using an unbounded hash-set approach when O(1) space via Floyd's cycle is expected in an optimal-space interview answer — both are correct, but know the tradeoff.
- For Plus One, forgetting the edge case where every digit is 9 (`999` → `1000`), which requires inserting a new leading digit rather than just propagating carry within the existing array.
